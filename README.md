# audio

> [!CAUTION]
> **All the code in this repository was generated by Claude, an AI from Anthropic, and has not been checked by a person.** It may have bugs or not do what it says. Read it before you rely on it, and use it at your own risk.

Sound in and out on Linux in Rust: zero third-party crates, nothing but std.
It speaks PulseAudio's native protocol over
its Unix socket, which PipeWire serves too (`pipewire-pulse`), so it works on
either; the server converts formats, rates and channel counts, and this side
only ever sees `f32` samples.

```rust
use audio::{Client, Spec, Tap};

let client = Client::connect("myapp")?;          // $PULSE_SERVER, else $XDG_RUNTIME_DIR/pulse/native
let stream = client.record(Some(audio::DEFAULT_MONITOR), Spec { rate: 48000, channels: 2 }, 512)?;
let tap = Tap::start(stream, 2.0)?;              // a thread keeps the last 2 s
let mut samples = Vec::new();
let total = tap.latest(4096, &mut samples);      // the newest 4096 frames, interleaved
```

| Item | What it does |
| ---- | ------------ |
| `Client::connect` | Connects, authorises (cookie, or none for PipeWire), names the client |
| `Client::server_info`, `sources`, `sinks` | The server, its defaults, and its devices (monitors included) |
| `Client::record` → `Record` | A capture stream: `read` waits for the next packet of samples |
| `Client::playback` → `Playback` | A playback stream: `write` waits while the server's buffer is full; `drain` |
| `Tap` | A `Record` read in a thread into a ring; `latest(n)` never waits; `read(from, n)` takes frames by number, `Gap::Gone` if the ring overwrote them, so a reader can take every frame and know when it fell behind; `total`, `capacity` |
| `Wav` | WAV files read (8/16/24/32-bit PCM, 32/64-bit float, extensible) and written (float) |
| `DEFAULT_MONITOR` | `@DEFAULT_MONITOR@`: what the default sink is playing |

The device for `record` is a source's name (`None`: the default source, usually a
microphone); a sink's monitor source records what that sink plays.

## Examples

```
cargo run --example devices            # the server, sources and sinks
cargo run --example meter [SOURCE]     # a level meter (default: what is playing)
cargo run --example tone [HZ] [S] [L]  # play a sine
```

## How it works

Packets are a 20-byte descriptor (length, channel, offset, flags; big-endian) and
a body. Commands and replies are tagstructs (`src/tagstruct.rs`: typed values,
each a tag byte and its bytes) on the control channel; sound travels on the
stream's channel inside the packet. No shared memory is asked for, so none is
used. Protocol version 32 is spoken (the server's if older; 13 at the least).
One connection carries one stream: `record` and `playback` take the `Client`.

## Use it

It isn't on crates.io; depend on it from git:

```toml
[dependencies]
audio = { git = "https://github.com/sawdustandswarf/audio" }
```
